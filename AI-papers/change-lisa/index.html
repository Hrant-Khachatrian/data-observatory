Dataset construction

The documented pipeline starts from existing masks

  1. A VLM describes a highlighted change region using both dates.
  2. A language model rewrites descriptions into instructions at L1–L3.
  3. Mismatched requests create negative examples.
  4. Experts filter the generated annotations.

The released generator is an outline. Its description, rewriting, and negative-generation functions raise NotImplementedError. The full construction pipeline cannot be reproduced from this script alone.

Documented process and implementation status: generator source. This inspection does not establish which VLM or verification procedure produced the final dataset.
Architecture

Language conditions a dense mask decoder

ComponentInput and role
Shared SAM encoderEncodes both temporal images into spatial features
Temporal alignment and fusionCombines the two features and their absolute difference
LLaVA with CLIP visual inputProcesses images and the request, producing a segmentation-token embedding
Text projection and SAM decoderUses the language embedding and fused spatial features to predict a mask

This architecture produces pixels directly. It does not rely on asking a general VLM to emit polygon coordinates.

Temporal evidence

The fusion retains both dates as well as their difference

g = sigmoid(Conv([f₁, f₂]))
f̃₁ = f₁ + g ⊙ f₁    f̃₂ = f₂ + g ⊙ f₂
d = |f̃₂ − f̃₁|
F = φ([f̃₁, f̃₂, d])

Absolute difference identifies discrepancy. Keeping the ordered temporal features also preserves information that can distinguish source and destination.

This is the inspected implementation’s shared residual gate. Its name “alignment” does not imply a separately verified geometric registration algorithm.

Simplified notation for compute_diff_features in model/LISA.py. φ uses lightweight 1×1 convolution layers.
Adaptation

Change-LISA learns task-specific parameters

Frozen in the inspected setup

  • SAM encoder backbone
  • CLIP vision tower
  • Multimodal projector

Trainable code paths

  • Language-model LoRA adapters
  • SAM mask decoder and text projection
  • Temporal gate and fusion layers
  • Token embeddings and language head

The abstract summarizes adaptation as LoRA plus decoder training. The public training script explicitly enables the additional modules listed here. Configuration matters when reproducing the method.

Source inspection: train_ds.py and model/LISA.py. This is supervised model adaptation, unlike frozen-weight prompt optimization.
Evaluation

The released evaluator separates positives and negatives

L1–L3: foreground masks

IoU = TP / (TP + FP + FN)

Computes IoU and F1 per sample, then averages over samples. The overall positive score combines samples from all positive levels.

L0: unwanted predicted area

FPA = predicted pixels / image pixels

Default NCA marks a sample correct when FPA is below 0.01. Thus the released evaluator tolerates a small nonempty prediction.

The script uses mask logits above zero as foreground. This aggregation differs from macro-averaging class/transition-pooled IoUs.

Definitions verified in evaluate_change_lisa.py, including default --nca_threshold=0.01.

What this paper leaves unresolved

Temporal discrimination remains a separate question

A successful instruction-conditioned mask does not, by itself, identify which temporal reasoning steps the model used.

  • Correct endpoint recognition versus correct relation selection
  • Source changes with a fixed destination and identical candidate regions
  • Equivalent wording versus changes in the intended predicate
  • Mask quality versus semantic selection under fixed geometry

These are candidate diagnostics for temporal evaluation. The accessible evidence does not establish that Change-LISA evaluated them, nor prove that they are new across the wider literature.

Interpretation based on the accessible task, taxonomy, samples, and evaluator. Full paper access would be needed for a complete audit of its ablations.
